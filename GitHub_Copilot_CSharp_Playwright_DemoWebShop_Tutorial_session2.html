Starting point: Registration is already complete. Continue with existing demo account → login → Books → Computing and Internet → Add to cart → validate quantity and product → Page Object Model → data-driven testing → troubleshooting.

Registered User→Login→Books→Select Book→Add to Cart→Assert Cart

03 · Login Test — No POM

Open /login manually. Inspect Email, Password, and Log in controls before accepting any Copilot locator.

GITHUB COPILOT PROMPT 
Create a single C# Playwright NUnit test Login_WithValidCredentials_ShouldSucceed for https://demowebshop.tricentis.com/login. Use PageTest, async/await, environment variables WEBSHOP_EMAIL and WEBSHOP_PASSWORD, and Playwright retrying assertions. Verify the authenticated account email. Do not use Thread.Sleep, Selenium APIs, hardcoded credentials, or POM yet. Explain locator choices and edit only the test file.
CSHARP
using Microsoft.Playwright;
using Microsoft.Playwright.NUnit;
using NUnit.Framework;

namespace WebShop.Playwright.Tests;

[TestFixture]
public class LoginTests : PageTest
{
    [Test]
    public async Task Login_WithValidCredentials_ShouldSucceed()
    {
        var email = Environment.GetEnvironmentVariable("WEBSHOP_EMAIL")
            ?? throw new InvalidOperationException("WEBSHOP_EMAIL missing");
        var password = Environment.GetEnvironmentVariable("WEBSHOP_PASSWORD")
            ?? throw new InvalidOperationException("WEBSHOP_PASSWORD missing");

        await Page.GotoAsync("https://demowebshop.tricentis.com/login");
        await Page.Locator("#Email").FillAsync(email);
        await Page.Locator("#Password").FillAsync(password);
        await Page.Locator("input.login-button").ClickAsync();
        await Expect(Page.Locator(".header-links .account"))
            .ToHaveTextAsync(email);
    }
}

Run the login test

POWERSHELL
$env:WEBSHOP_EMAIL = "your-registered-email@example.com"
$env:WEBSHOP_PASSWORD = "your-demo-password"
$env:HEADED = "1"
dotnet test --filter "Name=Login_WithValidCredentials_ShouldSucceed"
Validate sample selectors against the live DOM. The selectors shown are illustrative expected site selectors, not selectors confirmed by executing the browser test. Use a dedicated test account and do not commit secrets.

05 · Add to Cart and Verify

The goal is not simply to click a button. Assert confirmation, the exact product, and quantity in the shopping cart.

GITHUB COPILOT PROMPT 
Extend my passing Playwright scenario: on the Computing and Internet detail page, set quantity 1, add to cart, check success notification, open Shopping cart, verify the exact product row and quantity. Use Playwright auto-wait and retrying assertions. Do not use Thread.Sleep. Differentiate technical actions from business assertions.
CSHARP
await Page.Locator("input.qty-input").FillAsync("1");
await Page.Locator(".add-to-cart-panel input[type='button']")
    .ClickAsync();

await Expect(Page.Locator(".bar-notification.success"))
    .ToBeVisibleAsync();

await Page.GotoAsync("https://demowebshop.tricentis.com/cart");

var productRow = Page.Locator("tr.cart-item-row").Filter(new()
{
    Has = Page.GetByRole(AriaRole.Link, new()
    {
        Name = "Computing and Internet", Exact = true
    })
});
await Expect(productRow).ToHaveCountAsync(1);
await Expect(productRow.Locator("input.qty-input"))
    .ToHaveValueAsync("1");
State isolation: Cart quantity = 1 assumes the account begins with an empty cart for this book. Clear the demo account cart before the session; do not silently delete other users’ cart data. Reconfirm all cart selectors in DevTools.

Business verification checklist

  • Login succeeded (matching account email).
  • Correct book detail page opened.
  • Add to Cart action produced success feedback.
  • Exactly one matching product row is present.
  • Quantity for that row is 1.

07 · Implement Page Objects

Base/TestBase.cs

CSHARP
using Microsoft.Playwright.NUnit;

namespace WebShop.Playwright.Base;
public abstract class TestBase : PageTest
{
    protected const string BaseUrl = "https://demowebshop.tricentis.com";
    protected static string RequiredEnvironment(string name) =>
        Environment.GetEnvironmentVariable(name)
        ?? throw new InvalidOperationException($"Environment variable missing: {name}");
}

Pages/LoginPage.cs

CSHARP
using Microsoft.Playwright;
namespace WebShop.Playwright.Pages;
public class LoginPage
{
    private readonly IPage _page;
    public LoginPage(IPage page) => _page = page;
    private ILocator Email => _page.Locator("#Email");
    private ILocator Password => _page.Locator("#Password");
    private ILocator LoginButton => _page.Locator("input.login-button");
    public ILocator LoggedInAccount => _page.Locator(".header-links .account");
    public Task OpenAsync() => _page.GotoAsync("https://demowebshop.tricentis.com/login");
    public async Task LoginAsync(string email, string password)
    {
        await Email.FillAsync(email);
        await Password.FillAsync(password);
        await LoginButton.ClickAsync();
    }
}

Pages/HomePage.cs

CSHARP
using Microsoft.Playwright;
namespace WebShop.Playwright.Pages;
public class HomePage
{
    private readonly IPage _page;
    public HomePage(IPage page) => _page = page;
    public Task NavigateToBooksAsync() => _page.Locator(".top-menu")
        .GetByRole(AriaRole.Link, new() { Name = "Books", Exact = true }).ClickAsync();

    public BooksPage(IPage page) => _page = page;

Pages/ProductPage.cs

CSHARP
using Microsoft.Playwright;
namespace WebShop.Playwright.Pages;
public class ProductPage
{
    private readonly IPage _page;
    public ProductPage(IPage page) => _page = page;
    public ILocator ProductTitle => _page.Locator(".product-name h1");
    public ILocator SuccessNotification => _page.Locator(".bar-notification.success");
    public async Task AddToCartAsync(int quantity)
    {
        if (quantity < 1) throw new ArgumentOutOfRangeException(nameof(quantity));
        await _page.Locator("input.qty-input").FillAsync(quantity.ToString());
        await _page.Locator(".add-to-cart-panel input[type='button']").ClickAsync();
    }
}

Pages/CartPage.cs

CSHARP
using Microsoft.Playwright;
namespace WebShop.Playwright.Pages;
public class CartPage
{
    private readonly IPage _page;
    public CartPage(IPage page) => _page = page;
    public Task OpenAsync() => _page.GotoAsync("https://demowebshop.tricentis.com/cart");
    public ILocator ProductRow(string title) => _page.Locator("tr.cart-item-row")
        .Filter(new() { Has = _page.GetByRole(AriaRole.Link,
            new() { Name = title, Exact = true }) });
    public ILocator ProductQuantity(string title) =>
        ProductRow(title).Locator("input.qty-input");
}

08 · Complete NUnit Scenario

Tests should orchestrate page objects and own the business assertions.

CSHARP
using Microsoft.Playwright.NUnit;
using NUnit.Framework;
using WebShop.Playwright.Base;
using WebShop.Playwright.Pages;

namespace WebShop.Playwright.Tests;

[TestFixture]
public class ShoppingCartTests : TestBase
{
    [Test]
    public async Task RegisteredUser_CanAddBookToCart()
    {
        string email = RequiredEnvironment("WEBSHOP_EMAIL");
        string password = RequiredEnvironment("WEBSHOP_PASSWORD");
        string title = "Computing and Internet";
        var login = new LoginPage(Page);
        var home = new HomePage(Page);
        var books = new BooksPage(Page);
        var product = new ProductPage(Page);
        var cart = new CartPage(Page);

        await login.OpenAsync();
        await login.LoginAsync(email, password);
        await Expect(login.LoggedInAccount).ToHaveTextAsync(email);

        await home.NavigateToBooksAsync();
        await books.OpenBookAsync(title);
        await Expect(product.ProductTitle).ToHaveTextAsync(title);

        await product.AddToCartAsync(1);
        await Expect(product.SuccessNotification).ToBeVisibleAsync();
        await cart.OpenAsync();
        await Expect(cart.ProductRow(title)).ToHaveCountAsync(1);
        await Expect(cart.ProductQuantity(title)).ToHaveValueAsync("1");
    }
}
Do not run the independent LoginTests and ShoppingCartTests against shared cart state in uncontrolled parallel runs. The scenario is a reference implementation pending live DOM and account verification.

CSHARP
using System.Text.Json;
using WebShop.Playwright.Models;
namespace WebShop.Playwright.Utilities;
public static class TestDataLoader
{
    public static IReadOnlyList<Product> LoadProducts(string path)
    {
        var json = File.ReadAllText(path);
        var data = JsonSerializer.Deserialize<ProductData>(json,
            new JsonSerializerOptions { PropertyNameCaseInsensitive = true });
        return data?.Products ?? throw new InvalidDataException("Products missing");
    }
    private sealed class ProductData
    {
        public List<Product> Products { get; set; } = [];
    }
}

Copy JSON file to test output

XML
<ItemGroup>
  <None Update="TestData\products.json" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>

10 · Industrial Challenges & Fixes

Observed problemLikely root causeBetter solution
Strict mode violationMultiple Books linksScope to top menu; use semantic role + exact name
Intermittent timeoutWrong locator, blocked UI, slow state changeInspect DOM, trace, and retrying assertions; no fixed sleeps
Wrong cart quantityDirty user account or previous cart contentsEstablish explicit clean test data precondition
Book not foundDifferent title, unavailable book, site changesInspect accessible names; fail with meaningful assertion
Login unreliableAccount, rate limit, environment or auth issueCapture redacted diagnostics; don't bypass login
Tests fail in parallelShared mutable account/cartSeparate accounts/data; controlled setup and cleanup
GITHUB COPILOT PROMPT 
Analyze my Playwright failure using the NUnit message, locator, screenshot and trace. Classify it as selector, synchronization, test data, environment, business logic or application defect. Propose minimum-risk repair, identify verification steps, and avoid increasing timeouts arbitrarily. Do not delete assertions.

11 · Copilot Instructions & Review

Provide repository guidance to improve Copilot consistency. Create .github/copilot-instructions.md:

MARKDOWN
# WebShop C# Playwright Standards
- Use C# and Microsoft.Playwright.NUnit with NUnit.
- Keep test setup in Base, UI interactions in Pages, business assertions in Tests.
- Store domain data in Models and external datasets in TestData.
- Use async/await and stable, unique, verified locators.
- Prefer semantic locators and retrying Playwright assertions.
- Never use Thread.Sleep to mask synchronization bugs.
- Never duplicate PageTest browser lifecycle.
- Never hardcode credentials or commit secrets.
- Avoid shared mutable test state and order-dependent tests.
- Explain diffs and preserve passing behavior when refactoring.
- Do not invent DOM selectors or remove assertions to make tests pass.
- Build and run focused tests after each change.
GITHUB COPILOT PROMPT 
Review this C# Playwright NUnit repository as a senior SDET. Examine POM boundaries, locator resilience, waits, test isolation, security, duplication, assertion quality, parallel risks, diagnostics and CI readiness. Classify each issue as Critical/Major/Minor, include file, reason, proposed change and risk. Do not modify code yet.

Copilot working cycle

  1. Ask Copilot to inspect the current file and explain proposed changes.
  2. Specify one small, testable task.
  3. Review generated diff and verify selectors in browser.
  4. Run targeted NUnit test and capture evidence.
  5. Ask Copilot to diagnose exact failure, not to invent a workaround.
  6. Commit only reviewed and proven code.

12 · Selenium vs Playwright

TopicSelenium C#Playwright C#
Driver abstractionIWebDriverIBrowser / IBrowserContext / IPage
ElementIWebElementILocator
NavigationNavigate().GoToUrl()GotoAsync()
Text entrySendKeys()FillAsync()
ClickClick()ClickAsync()
SynchronizationExplicit waits typically usedBuilt-in actionability + retrying assertions
Test assertionsNUnit + custom synchronizationPlaywright Expect with NUnit
IsolationCustom driver lifecyclePageTest / isolated context fixtures
DiagnosticsDriver screenshots + toolsScreenshots and tracing
Auto-waiting does not replace verifying business outcomes. Playwright waits for actions to become actionable; testers still define the expected state.
